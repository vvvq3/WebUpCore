## 0. Коротко: что такое этот сайт

- **Полностью статический сайт.** После сборки получается папка `site/dist/` с готовыми HTML, CSS, JS, шрифтами и картинками (~5,5 МБ, 17 страниц). Серверный код не нужен — только раздача файлов.
- **Единственная «серверная» часть — приём заявок с формы** (`site/deploy/form-handler.php` или любой аналог, см. раздел 5).
- Хостинг — **в РФ** (152-ФЗ: персональные данные из заявок должны собираться на серверах в РФ).
- Подходит любой хостинг: обычный виртуальный хостинг с PHP, VPS с nginx, Yandex Cloud Object Storage + CDN, Selectel, VK Cloud, Timeweb, REG.RU и т. п.

| Что | Где |
|---|---|
| Исходники сайта | `site/` (Astro 5 + TypeScript + Tailwind 4) |
| Тексты и вёрстка страниц | `tools/content/build_pages.py` → `python3 tools/content/export_web.py` → `site/src/generated/` |
| Готовый сайт после сборки | `site/dist/` |
| Обработчик формы (почта + Telegram) | `site/deploy/form-handler.php` |
| Пример конфигурации nginx | `site/deploy/nginx.conf` |
| Пример автодеплоя GitHub Actions | `site/deploy/deploy.yml.example` |
| Показ для коллег (не боевой) | https://vvvq3.github.io/WebUpCore/ — `.github/workflows/pages.yml` |

## 1. Что нужно заранее

1. **Хостинг в РФ** с HTTPS. Варианты:
   - **виртуальный хостинг с PHP** (самый простой: сайт + обработчик формы на одном хостинге, почта через mail()/SMTP хостинга);
   - **VPS с nginx + PHP-FPM** (полный контроль, конфиг — `site/deploy/nginx.conf`);
   - **Yandex Object Storage + Cloud CDN** (статика) + **Yandex Cloud Functions** для формы (без PHP — см. 5.3).
2. **Домен up-core.ru** — A/AAAA-записи (или CNAME для CDN) на новый хостинг. Старый сайт этим заменяется.
3. **SSL-сертификат** (Let's Encrypt у хостинга или certbot на VPS). Сайт рассчитан на `https://up-core.ru` (канонические ссылки, sitemap, Open Graph).
4. **Node.js 20+** на машине, где собирается сайт (локально или в GitHub Actions). На сервере Node не нужен.
5. По желанию:
   - **номер счётчика Яндекс Метрики** (раздел 6);
   - **Telegram-бот** для заявок (раздел 5.2).

## 2. Сборка

```bash
cd site
npm ci                # первый раз (или npm install)
npm run build         # результат — site/dist/
npm run preview       # проверить локально: http://localhost:4321
```

### Переменные окружения сборки (`site/.env`, образец — `site/.env.example`)
Задаются **при сборке** (вшиваются в HTML), на сервере их нет.

| Переменная | Что делает | Боевое значение |
|---|---|---|
| `PUBLIC_FORM_ENDPOINT` | адрес обработчика заявок (POST, multipart/form-data) | `/api/lead.php` (свой обработчик на хостинге в РФ) |
| `PUBLIC_FORM_EMAIL` | почта для запасного варианта (открыть письмо с заявкой) | `office@dex-it.ru` |
| `PUBLIC_YM_ID` | номер счётчика Яндекс Метрики; пусто — аналитики и cookie-баннера нет | номер счётчика |

Пример `site/.env` для боевой сборки:
```
PUBLIC_FORM_ENDPOINT=/api/lead.php
PUBLIC_FORM_EMAIL=office@dex-it.ru
PUBLIC_YM_ID=12345678
```

> **Важно:** на GitHub Pages сейчас стоит `PUBLIC_FORM_ENDPOINT=https://formsubmit.co/ajax/office@dex-it.ru` (зарубежный сервис — только для показа коллегам). Для up-core.ru его **не использовать** — свой обработчик в РФ.

### Боевая сборка ≠ сборка для GitHub Pages
- **Боевая** — `npm run build` → `site/dist/` как есть: абсолютные ссылки (`/grade/`), canonical и sitemap на `https://up-core.ru`, robots.txt разрешает индексацию.
- **GitHub Pages** — то же + `python3 tools/content/preview_bundle.py --pages ghp` (относительные ссылки для адреса `/WebUpCore/`, `noindex`, запрет в robots.txt). На боевой хостинг **не** выкладывать папку `ghp`.

## 3. Публикация файлов

Выложить **содержимое** `site/dist/` в корень сайта (document root), например `/var/www/up-core.ru/`.
Структура: `index.html`, `grade/index.html`, `ai/…`, `projects/…`, `mentor/…`, `blog/…`, `en/…`, `_astro/` (CSS/JS/шрифты с хэшами), `img/`, `og/`, `favicon.svg`, `robots.txt`, `sitemap-index.xml`, `sitemap-0.xml`, `404.html`.

Способы:
- **SFTP / панель хостинга** — загрузить файлы вручную (для первого запуска достаточно).
- **rsync по SSH** — `rsync -avz --delete site/dist/ user@server:/var/www/up-core.ru/` (флаг `--delete` убирает старые файлы; осторожно — не удалите `api/lead.php`, см. ниже: держите его в `site/public/api/`, тогда он входит в сборку).
- **Автодеплой** через GitHub Actions — раздел 8.

## 4. Настройка веб-сервера

Готовый конфиг nginx — `site/deploy/nginx.conf`. Что обязательно настроить на любом хостинге:

1. **Адреса со слешем на конце.** Страницы лежат как `grade/index.html` → адрес `/grade/`. Сервер должен отдавать `index.html` из папки (на обычных хостингах так по умолчанию). Адрес без слеша (`/grade`) лучше перенаправлять 301 на `/grade/`.
2. **404.** Для несуществующих адресов отдавать `/404.html` со статусом 404.
3. **Сжатие gzip/brotli** для HTML, CSS, JS, SVG, JSON, XML — без него страницы примерно в 5 раз тяжелее (стили встроены в HTML).
4. **Кэш:**
   - `/_astro/*` — надолго (`Cache-Control: public, max-age=31536000, immutable`): имена файлов меняются при каждой сборке;
   - `/img/*`, `/og/*`, шрифты — долго (например, 30 дней);
   - HTML — без долгого кэша (`no-cache`), чтобы правки появлялись сразу.
5. **HTTPS** и перенаправление `http → https`, `www.up-core.ru → up-core.ru`.
6. **Заголовки безопасности** (рекомендуется): `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: SAMEORIGIN`. Если включаете CSP — разрешите `mc.yandex.ru` (Метрика) и `'unsafe-inline'` для стилей/скриптов (стили и небольшой скрипт встроены в страницы).
7. **Перенаправления со старого сайта up-core.ru.** Если у старого сайта были другие адреса (страницы, блог), настройте 301 на ближайшие новые (`/`, `/grade/`, `/ai/`, `/projects/`, `/mentor/`, `/blog/`), чтобы не потерять позиции в поиске и старые ссылки.

## 5. Приём заявок с формы

Форма одна на весь сайт (кнопки «Провести демо», «Открыть демо», «Открыть демо-стенд», «Посмотреть демо-стенд», «Получить пример отчёта», «Заказать аудит», «Заказать бесплатный пилот»). Тема заявки: `demo`, `report`, `audit`, `pilot`.
Поля: `name` (обязательно), `company`, `team`, `contact` (обязательно), служебные `topic`, `page`, `lang`, `website` (ловушка для ботов — должна быть пустой).

**Как работает:** если задан `PUBLIC_FORM_ENDPOINT`, форма отправляет POST (multipart/form-data, заголовок `Accept: application/json`) и ждёт ответ `200` с JSON, где нет `"ok": false` / `"success": false`. Тогда показывает «Заявка отправлена».
Если обработчик не ответил или вернул ошибку — **заявка не теряется**: у посетителя открывается письмо на `PUBLIC_FORM_EMAIL` с заполненными полями.

### 5.1. Свой обработчик на PHP (рекомендуется) — почта + Telegram
1. Скопировать `site/deploy/form-handler.php` в `site/public/api/lead.php` (тогда он попадает в каждую сборку и выкладывается вместе с сайтом) — или положить на сервер вручную в `/api/lead.php`.
2. При сборке: `PUBLIC_FORM_ENDPOINT=/api/lead.php`.
3. Почта уходит через `mail()` на `office@dex-it.ru`. Для надёжной доставки лучше настроить у хостинга отправку через SMTP (или заменить `mail()` на PHPMailer/SMTP), а для домена up-core.ru — записи SPF/DKIM, чтобы письма не уходили в спам. Отправитель в обработчике — `no-reply@up-core.ru`.
4. Проверка: отправить заявку с сайта → письмо пришло; в devtools запрос `/api/lead.php` → 200 и `{"ok":true}`.

### 5.2. Заявки в Telegram
1. В Telegram открыть **@BotFather** → `/newbot` → получить **токен** вида `123456:ABC…`.
2. Написать новому боту `/start` (иначе бот не сможет писать вам).
3. Узнать свой **chat id**: открыть в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найти `"chat":{"id":…}` (для группы — добавить бота в группу, написать в неё сообщение, id будет отрицательным).
4. Задать на сервере переменные окружения PHP: `TG_BOT_TOKEN` и `TG_CHAT_ID` (в панели хостинга, в `php-fpm` pool: `env[TG_BOT_TOKEN]=…`, или `SetEnv` в `.htaccess` на Apache).
5. Обработчик сам отправит каждую заявку и письмом, и в Telegram.
> Токен бота нельзя класть в код страницы или в репозиторий — только в переменные окружения сервера.

### 5.3. Без PHP (статика в Object Storage)
Если сайт лежит в Yandex Object Storage, обработчик делается **Yandex Cloud Function** (Node.js или Python) с HTTP-триггером: принимает multipart/form-data, шлёт письмо (Yandex Cloud Postbox / SMTP) и/или сообщение в Telegram, отвечает `{"ok":true}` и заголовком `Access-Control-Allow-Origin: https://up-core.ru`. Логика — как в `form-handler.php`. Адрес функции — в `PUBLIC_FORM_ENDPOINT`.

### 5.4. Персональные данные (152-ФЗ)
- Заявки содержат имена и контакты — **собирать и хранить их на серверах в РФ** (свой обработчик на хостинге в РФ, не FormSubmit).
- Под кнопкой формы уже есть текст о согласии на обработку контактных данных. До запуска рекомендуется сделать страницу **«Политика обработки персональных данных»** и поставить ссылку в подвале и в форме (страница запланирована, пока не сделана).
- Уведомление Роскомнадзора об обработке ПДн — по решению юристов Dex.

1. Создать счётчик на https://metrika.yandex.ru для up-core.ru (Вебвизор — по желанию).

## 8. Автодеплой через GitHub Actions

Шаблон — `site/deploy/deploy.yml.example` (скопировать в `.github/workflows/deploy.yml` и заполнить). Сценарий: push в ветку релиза → `npm ci && npm run build` с боевыми переменными → выкладка `site/dist/` на сервер (rsync по SSH) или в Object Storage.
Секреты репозитория (Settings → Secrets and variables → Actions): `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_PATH`, `DEPLOY_SSH_KEY` (закрытый ключ, публичный — в `~/.ssh/authorized_keys` на сервере), при необходимости `PUBLIC_YM_ID`.
Для Object Storage вместо rsync — `aws s3 sync site/dist/ s3://<бакет>/ --endpoint-url=https://storage.yandexcloud.net --delete` с ключами сервисного аккаунта в секретах.

## 10. Нюансы работы системы (важно знать)

**Тексты и страницы**
- Вёрстка страниц **не пишется в Astro руками** — её генерирует `tools/content/build_pages.py`. Правка → `python3 tools/content/export_web.py` → `npm run build`. Файлы `site/src/generated/*` и `site/src/styles/generated.css` вручную не править — перезапишутся.
- Действующая (новая) версия RU-страниц: `home_v2`, `grade_v2`, `ai_v2`, `proj_v2`, `mentor_v2`, `blog_v2` (по ТЗ владельца, PDF в `docs/content/`). Подключение — `RU_OVERRIDES` в `tools/content/export_web.py`. Прежние функции (`home('A')`, `grade_page(3)` и др.) остаются для холста дизайна и английской версии.
- Общие блоки новой версии: `header_v2()` (шапка «Провести демо» + «Открыть демо»), `saas_v2()` («Подключение за минуты»), `cta_v2()` (синий блок: «Заказать бесплатный пилот» + «Открыть демо-стенд»), `hero_ctas_v2()`.
- Все «демо»-кнопки открывают **форму «Провести демо»**, а не demo.up-core.ru.

**Английская версия**
- `/en/...` — перевод **новой** версии страниц (раунд 94) по словарю `site/i18n/en.json` (ключ — русская строка, значение — английский). Переключателя языков на сайте нет (решение владельца), EN-страницы доступны по прямым адресам, есть в sitemap и hreflang.
- В EN **нет блога** (раунд 95). Суммы в рублях на EN-страницах автоматически пересчитываются в доллары (100 ₽ = $1, целые числа) — `rub_to_usd` в `tools/content/translate_web.py`; курс — `RUB_PER_USD`. Шрифт текстов EN — Onest (как кириллица в RU), цифры-табло и названия продуктов — Bricolage.
- После правки русских текстов: `python3 tools/content/translate_web.py --missing` → перевести строки из `site/i18n/missing.json` в `en.json` → `export_web.py`. Без перевода новая строка попадёт на EN-страницу по-русски.

**Форма**
- Тема заявки задаётся атрибутом `data-form` у кнопки; заголовки и тексты формы — `site/src/data/i18n.ts` (`form.titles`, `form.leads`).
- На телефоне при открытии курсор не ставится в поле (фокус на окне), на компьютере — сразу в «Имя».
- Запасной вариант без обработчика — письмо (mailto) с заполненной заявкой.

**Анимации** (`docs/design/ANIMATIONS.md`, код — `site/src/scripts/site.ts`)
- Цифры-табло на первом экране крутятся сразу при открытии; остальные — при прокрутке; есть «страховка» для быстрой прокрутки (End, переход по якорю) — ничего не остаётся невидимым.
- Слайдер на главной — 14 скриншотов (`docs/reference/demo/screens/`, список `SCREENS` в `build_pages.py`), полоса 1,5 с без пауз, пауза при наведении мыши и вне экрана. Заменить скриншоты — положить PNG и поправить `SCREENS`, затем `export_web.py`.
- Блок «160 ч → 80 из 160» запускается, когда карточка появилась в нижней части экрана.
- При системной настройке «уменьшить движение» анимации выключены.

**Шапка и адаптив**
- ≥1360 px — полное меню; 1161–1359 px — компактное; ≤1160 px — логотип, «Открыть демо» и бургер (меню на весь экран, внизу телефон и Telegram).
